# 随身音乐

随身音乐是一款面向 iPhone 与 Apple Watch 的离线音乐播放器，提供本地音乐管理、独立播放和局域网传输。本仓库包含运行所需的源码、工程、资源和测试，使用正式工程与应用标识，无需原项目目录。

```sh
git clone git@github.com:blueautume/WatchMusic.git
cd WatchMusic
git switch main
open WatchMusic.xcodeproj
```

功能开发从 `main` 新建分支。应用采用双端前台局域网传输，两端播放独立，不同步或互相控制播放。

## 界面语言

iPhone 和 Apple Watch 均支持简体中文与英文，跟随各自设备的系统语言或系统中的 App 语言设置；其他语言在没有匹配资源时使用英文。中文应用名称为“随身音乐”，英文为“WatchMusic”。音乐库、播放与队列、传输状态、设置、错误提示、权限说明和无障碍标签均提供双语文案；iPhone 的隐私协议、用户协议和支持页也可离线阅读英文版本。

歌曲标题、艺术家、专辑、目录名和文件名保留原始内容。历史传输状态与另一台设备发来的消息在显示时转换为本机语言，无需改写既有队列。短屏幕上的长标题使用适当的短标题，正文可以换行或滚动；辅助功能大字下的协议操作按钮改为纵向排列。

双语资源位于 `Shared/en.lproj` 和 `Shared/zh-Hans.lproj`，两端权限与应用名分别位于各 target 的 `InfoPlist.strings`。运行 `Tests/run-localization-tests.sh` 检查翻译覆盖、格式参数、英文回退、跨语言历史消息和离线协议；构建后可运行 `python3 Tests/check-localization.py --bundle /path/to/WatchMusic.app`，同时检查手机与内嵌手表的实际资源。

## 打开与运行

打开 `WatchMusic.xcodeproj`：

- iPhone scheme：`WatchMusic`
- Apple Watch scheme：`WatchMusicWatch`
- iPhone Bundle ID：`com.lihao.WatchMusic`
- Watch Bundle ID：`com.lihao.WatchMusic.watchkitapp`
- 桌面名称：`随身音乐`；版本 `1.0.4 (5)`

每次修改后打包新构建时，同时递增版本号和构建号，确保 iPhone 与 Watch 的 Debug、Release 配置一致。

两个 target 继续使用原工程的开发团队与自动签名配置。真机运行时由 Xcode 为新 ID 创建相应描述文件。最低 iOS 17 / watchOS 10；手表双指互点下一首需要 watchOS 11 和支持该手势的设备。

正式版使用新的 Bundle ID，因此会作为独立应用安装，不会自动继承旧实验版沙盒中的歌曲、播放偏好或协议同意记录。旧版应用及其原有音乐、数据仍保留；如需继续使用已有音频，请从原始文件重新导入并传到正式版手表应用。

## 隐私协议与技术支持

iPhone 首次启动会全屏展示协议入口，明确同意后才初始化音乐库、播放器与传输服务；本机记录当前协议版本和同意时间，再次启动直接进入。取消保持未进入状态，协议版本更新后重新询问。传输页右上角、清理按钮左侧的设置仅提供“隐私协议”和“关于”，可离线阅读隐私协议、用户协议，以及撤回同意。撤回会停止本机播放和传输、清除同意记录，保留音乐与传输队列；Apple Watch 不添加签署流程。

可部署的 [隐私协议](PhoneApp/Legal/privacy.html)、[用户协议](PhoneApp/Legal/terms.html)、[技术支持](PhoneApp/Legal/support.html) 也是应用内的离线文档，避免分别维护内容。运行 `bash Website/package.sh` 生成 [静态网页压缩包](Artifacts/Deployment/watchmusic-web-2026-10-29.zip)，解压上传即可；详见 [部署说明](Website/README.md)。网页支持深浅色模式，无外部依赖或追踪代码。开发者：李浩（个人开发者），支持邮箱：2114581274@qq.com。

## 功能范围

- 手机：音乐库和传输两个入口，导入 MP3 / FLAC，管理目录、本地播放和发送到手表。音乐库根页仅展示目录和新建入口；先建目录，再在目录内导入。长按歌曲进入多选，右上角“操作”菜单提供批量发送、移动、删除，旁边“完成”退出选择；同名目标不覆盖，部分失败会汇总提示。
- 手表：单页播放器，按歌曲信息、四个图标操作、上一首/播放暂停/下一首纵向排列；模式、速度、睡眠定时和音频输出直接操作，表冠交给系统本地音量控件，页面统一采用自定义返回按钮；系统导航栏隐藏，避免挤占曲面屏幕。移除播放进度条和拖动手势。
- 移除歌词解析、显示、校准与传输，以及外部歌词/封面资源管理。歌曲内嵌标题、艺术家和封面继续显示。
- 两端独立本地播放，保留离线播放、后台音频、系统锁屏/耳机控制、播放恢复、模式、倍速、音量和睡眠定时；不交换播放状态，也不控制另一台设备。
- 系统控制中心和锁屏播控使用上一首、播放/暂停、下一首，关闭前后跳秒命令；系统进度拖动保留。
- 手机播放条固定叠放在标签栏上方，两侧留边距，不参与目录列表的纵向排版；去掉拖动和悬浮球。目录、歌曲及传输列表只在播放条存在时追加可滚动尾部空白，最后一项可滚到条上方。播放页模式、速度、睡眠和输出统一为四个无文字图标；不提供独立应用音量，音量由系统控制，升级时移除旧应用增益偏好。应用配色跟随系统深浅色模式。
- 新图标沿用参考图的手表与音符轮廓，以蓝色作为应用主题；iPhone 提供浅色与深色图标，Watch 使用适配圆形裁切的深色版本。[生成提示词及导出说明](Brand/IconPrompt.txt)。
- 文件管理只修改所在设备的副本。

手机播放页按可用高度和文字实际高度布局，优先扩大封面，再分配区块间距，底部操作保留适量边距；小屏、大字或开启定时时可以滚动。手表播放器的原生音量控件常驻在不透明页面背景后，不改变页面布局；进入播放器、开始播放或关闭弹层后请求表冠焦点，离开或进入后台时释放。真实系统音量变化时，当前页面右上角从右侧滑入无文字和图标的竖向细音量条，填充自下向上随音量平滑过渡，最后一次变化约 1.4 秒后向右滑出隐藏；屏幕旋转后仍固定在当前页面右上角，独立于实体表冠位置。打开弹层、选择输出、离开页面或进入后台时清理提示。音量已到上下限后的空转不产生音量变化事件。播放页的双指互点两次绑定下一首，在页面前台可见且已选歌曲时启用，弹层和输出选择期间暂停手势；普通界面绑定下一首按钮，沉浸界面绑定可见封面。

手表本地播放继续通过系统音频会话、Now Playing 信息和远程命令提供系统播控，歌曲、播放状态与队列调整同步到系统。表盘上划打开的智能叠放由 watchOS 决定是否呈现媒体卡片；如未显示，检查手表“设置 → 智能叠放 → 实时活动”相关开关，详见 [Apple 实时活动说明](https://support.apple.com/zh-hans/guide/watch/bz1vx4mwqbw9/watchos)。App 无公开 API 强制插入或置顶这张系统卡片。单次捏合与辅助触控手势由系统设置管理；本 App 的快捷手势使用 watchOS 11 的双指互点两次。

## Watch 播放页封面与沉浸模式

Apple Watch 播放页使用当前歌曲的封面作为模糊背景，覆盖返回按钮、时钟周围与播放控制区域，并随充电显示方向一起旋转。背景复用封面缩略图，叠加从上到下加深的遮罩，保留文字和按钮的对比度。无封面、解码失败、开启降低透明度或屏幕降低亮度时使用纯色背景。增强对比度时进一步减弱背景。

背景底层始终不透明，遮住后方常驻的系统表冠音量控件，原有表冠、音量提示与双指操作继续使用。模拟器预览及验证记录见 `Verification.md`，截图位于 `Artifacts/Previews/ArtworkBackground`。

手表播放页在没有触屏操作 5 秒后进入沉浸模式，封面平滑放大，歌名移到封面下方居中，歌手、操作按钮和返回按钮淡出。点击页面任意位置恢复原界面，随后重新计满 5 秒。常亮屏变暗时保留等待截止时间和当前布局。若系统推迟了页面更新，唤醒时按原截止时间继续。已选歌曲的暂停状态也可进入，沉浸中的自动切歌保留当前模式。打开弹层、选择输出、离开播放页或进入后台时取消等待，返回后重新计时。播放准备期间暂不开始新的等待，降低动态效果时直接切换布局。相关状态与布局测试为 `Tests/run-watch-immersive-tests.sh`，预览位于 `Artifacts/Previews/ImmersivePlayback`。

横屏沉浸模式将封面与歌名作为一个整体上下居中，上下各留至少 12pt；按歌名的实际行高计算位置，继续避让系统时钟。

## Watch 音频输出

点播放时通过 watchOS 的长音频会话激活输出；没有可用输出时由系统显示设备选择界面，可选择耳机、HomePod 等输出。这次明确的播放请求会保留，原生激活成功并返回播放页后继续原歌曲及进度。激活成功不以供图标显示的路由快照非空为前提，避免快照更新延迟或虚拟路由过滤导致按钮一直停在准备状态。

音频输出按钮使用同一原生输出选择流程，只选择设备，不创建播放请求。系统可能直接采用已有可用输出；设备列表的呈现与可选端点由 watchOS 管理。

音频会话的同步配置与停用由专用串行后台队列执行，相同配置不重复设置，结果回主线程更新播放器。空闲且没有可用输出时，输出按钮先释放已准备的音频资源并完成会话停用，再重新激活长音频输出，避免复用残留的激活状态。正在播放时保留现有音频。

未选择设备直接返回时，清除本次待播请求、恢复播放按钮，保留歌曲及进度，不弹出“音乐提示”或“恢复播放失败”。之后单独连接设备不会触发已取消的播放。音频配置、文件解码错误，以及已有输出时的激活失败仍显示提示；主动暂停、停止或真正断开输出也会取消待播请求。

输出按钮在没有外设路由时显示灰色原图标，已连接时变蓝。可识别的 AirPods、AirPods Pro、AirPods Max 分别显示各自的 AirPods 图标；其他耳机、HomePod / HomePod mini 和车载输出使用对应图标。未知或改名后无法识别的设备保留原图标，连接状态仍由当前实际路由决定。系统只提供端口类型和名称，蓝牙或 AirPlay 协议本身不代表设备型号；内置扬声器和虚拟路由不算已连接外设。支持机型仍可按系统许可使用内置扬声器播放。

## 传输进度

所有新发送和重试均使用局域网传输：手机临时提供文件下载服务，手表通过 HTTP 接收并校验后保存。手机“传输”页分为“进行中”和“已传输”两个标签，无需选择传输方式。旧版普通 WatchConnectivity 任务的历史记录、取消和保存回执继续兼容，重试时统一走局域网。[传输说明与测试步骤](LANTransferExperiment.md)

TestFlight `1.0.6 (8)` 的真机反馈仍未达到熄屏持续下载目标：iPhone 始终前台，同一首歌曲传到中途时手表熄屏后停止，点亮后从原进度继续。`1.0.7 (9)` 是诊断与容错构建，不标记问题已经解决。模拟器切换到“设置”App 验证的是后台生命周期，不能代表硬件屏幕关闭；真正触发点仍需设备复现数据确认，尚未证实是网络接口或权限问题。

点击发送后，已接受的歌曲立即写入持久队列，在“进行中”显示准备或等待状态，并可直接取消。后台预检更新同一条任务，按目录、文件名、大小和 SHA-256 核对手表实际库存。内容相同的歌曲无需再次发送，同路径已有有效任务时会合并。单个源文件无法读取时，该项显示失败，同批其他有效歌曲继续。手表指纹缓存独立于手机传输历史，清空记录后仍可去重。手表已删除歌曲或同名文件内容不同时可以重新发送。

传输时可以继续从其他目录或列表添加歌曲，手机按加入顺序维护全局等待队列；一次选择超过 100 首时，App 自动拆为每批最多 100 首。手表接受清单后，将该批所有未暂停文件一次提交给系统后台 URLSession，下载不再依赖 App 逐首唤醒。系统决定网络任务的调度顺序和并发，文件校验与原子保存仍在单一队列完成。当前批收到全部终态确认后才启动下一批；启动新批次仍需手表 App 活跃且实时可达，后续等待项不会在手表不可达时自行握手。

“进行中”先显示正在传输或部分接收的任务，进度暂时停滞时保留优先位置；之后依次是校验或等待确认、按加入顺序准备或排队、已暂停任务，以及可重试的失败和本地已更新记录。“已传输”仅包含手表已确认保存的记录，按发起时间从新到旧排列。已取消记录从两个标签及其计数中排除。列表排序独立于持久化历史和每首歌曲的最新记录。

传输页不提供多选或更多菜单。“暂停 / 开始”切换全部可操作任务，也覆盖手机本地等待项；单项保留独立暂停、继续和取消，校验保存阶段不暂停。全局暂停时，随后追加的任务也以暂停状态等待。右上角清扫图标清除当前标签的全部任务或已传输记录。清除会先取消相关传输再移除记录，不删除两端已经保存的音乐，也不撤销已经完成的保存。

已提交到手表的暂停和继续需要实时可达并确认，不可达或未确认时不会假报暂停；手机本地等待项可直接暂停、开始和清除。暂停挂起对应系统任务，保留已接收大小及百分比，隐藏速度和剩余时间；暂停时已完成的下载可保留暂存文件，恢复后再校验保存。当前批仍有暂停项未结束时，后批继续等待，不承诺跨批越过这些暂停项。旧版普通传输任务不支持此暂停，可取消后从音乐库重新发送。

LAN 接收开始后，手表自动进入专用全屏接收页，显示进度、歌曲和批次，完成或取消后自动返回音乐库。充电或满电仍接电时，整个手表 App 默认通过 CoreMotion 重力识别四个显示方向，音乐库、播放器和接收页使用同一方向，并修正左侧表冠的坐标，无需旋转设置按钮。平放或运动数据不可用时保留最近稳定方向；检测到拔电后固定为佩戴时的竖屏，停止方向采样。进入后台也停止采样，回到前台时重新读取充电状态。

手表音乐库标题“随身音乐”之后显示本机电量百分比，充电时显示充电状态；电量尚不可读时显示未知状态，不把它当成 0%。标题电量随应用充电方向旋转，不再保留独立电量栏。watchOS 26.5 模拟器中公开隐藏请求未能可靠隐藏系统时钟，因此保留一个系统时间，其方向仍由系统控制，应用不绘制第二个时钟。应用使用完整物理画布旋转，不扣除一整条时钟区域；只对文字和点击区域做时钟角落避让，列表卡片可继续显示到曲面边缘，无固定底部黑条。

开始新批次时，两台设备需连接能互相访问的同一 Wi-Fi，两端 App 均处于活跃状态。手机前台传输期间请求保持屏幕常亮，结束后恢复原设置。手机转为 `inactive` 或 `background` 时暂停队列并关闭文件服务。手表的 `inactive`、`background` 和熄屏不再主动取消已经提交的下载；系统可在 App 挂起后继续传输，完成事件由系统安排交付。下载时机、网络并发与后台唤醒仍受 watchOS 调度，不能保证持续保持前台速度。

手表不再依赖防自动息屏请求维持下载。屏幕亮度、Always On 和显示时长由设备及用户设置决定；显示方向和电量采样仍只在前台运行。WatchConnectivity 暂时不可达时，手机保留已经确认的 HTTP 文件源，重连后先查询当前批次状态，避免为仍在下载的批次重复握手或重建服务。

等待队列和暂停意图持久保存。手表进程重建后，以相同后台会话标识重新关联系统任务，按会话和文件身份对账；已下载文件从持久暂存区继续校验，不再统一取消旧任务。手机重启或文件源失效时重新验证源文件和手表库存，必要时建立新清单，未完成单曲可能重新下载。源文件版本未变化时复用本进程已验证的 SHA-256，避免预检、库存及建源重复读取；源内容变化时要求重新发送。清除任务会使旧准备工作和迟到消息失效，不会重新创建已清除的队列。

iPhone 的“传输 → 设置”显示手表是否已配对、已安装 App 和当前是否可连接，并显示手表回复的自身版本及后台下载能力。offer 接受确认和库存回复外层带 `receiverVersion`、`receiverBuild`、`supportsBackgroundDownloads`；旧版回复缺少这些字段时显示未知，仍保持兼容。手表“存储与连接”页也显示自身 Bundle 版本及构建号，验收前需核对手机和手表实际都已更新。开始局域网传输时请保持两端 App 打开。

手机源服务和清单有效期最长 1 小时；手机离开前台、服务过期或网络失效仍会中断源可用性，不能据此承诺任意后台或无限续传。手机队列不保存旧服务凭据；手表清单、任务身份、暂存文件和终态回执保存在受文件保护、排除备份的 Application Support 文件中，令牌不进入正式日志或用户传输记录。后台 URLSession 自动跟随重定向，App 无法通过重定向委托阻止该请求；保存前严格检查最终端点、完整大小、SHA-256 和音频有效性，端点变化的文件拒绝保存。

手机 HTTP 请求头接收超时为 20 秒，传输空闲超时为 300 秒；后者按发送处理进展续期，两者都受文件源一小时总有效期约束。该调整用于容忍短时停滞，尚不能证明已经修复真实熄屏停传。

后台事件处理等待当前委托回调和校验落盘完成，再释放 WatchKit 后台执行机会；系统提前收回执行时间时，保留已下载文件，后续唤醒或回前台继续校验。模拟器覆盖真实后台状态、系统任务和进程重关联；硬件熄屏、无线链路及 TestFlight 效果需由脱离调试器的真机测试确认，实际验证结果见 [验证记录](Verification.md)。

局域网进度使用手表实际接收字节；已有普通传输任务仍通过 WatchConnectivity 原生 `WCSessionFileTransfer.progress` 读取进度，并用进度比例与源音频大小换算已传大小。速度与剩余时间由近期采样估算，界面以“约”标注。系统尚未开始发送、进度停滞或等待保存回执时不显示虚假的速度与时间。

手机另记录 `sourceBytes`：它是本次 HTTP 请求的 Range 起始偏移，加上已交给网络栈处理的音频字节，表示源端逻辑文件位置。它不代表手表已经收到、校验或保存，也不替代手表确认进度；重试不会把重复发送的流量累加成完成进度。真实 HTTP 读取可以在 offer 确认迟到时证明该源已被访问，取消、清除或更换源后丢弃过期的源进度回调。

Release 系统日志在手表回到 active 时查询一次 native task 状态和接收字节，任务完成时记录协议、代理标志和各网络阶段时间；手机源日志独立记录发送位置、连接关闭及超时原因。日志不包含 URL、IP、令牌或歌曲名，也不使用定时轮询。这些证据用于区分源端停发、系统下载等待和 WatchConnectivity 进度迟报。

传输达到 100% 只表示发送阶段完成；只有手表完成文件校验、写入并返回成功回执后，手机才显示“已保存到手表”。单项时间估算针对该歌曲；“传输”标题旁的总剩余时间聚合当前与排队歌曲，使用平滑速度与粗粒度更新，暂停或速度未知时隐藏。保存开销和无线速度变化会影响实际完成时间。

播放位置从原生播放器时钟读取，仅局部进度视图使用 TimelineView；睡眠定时使用一次性截止任务。传输进度从真实接收事件及旧系统任务 Progress 观察更新，独立于音乐库模型，避免菜单随全页定时发布而闪烁。

暂停后进入后台，或后台播放被暂停、睡眠定时及耳机断开停止时，两端播放器释放已准备的音频硬件并停用音频会话，保留歌曲、进度、队列、倍速和系统播控；继续播放时重新准备输出。前台短暂停保持原有快速续播和表冠音量体验，系统输出选择造成的 inactive 状态不触发后台清理，真实后台播放及有效的播放准备也不会被中断。迟到的音频激活结果按当前播放意图收尾，不重新开始已取消的播放或关闭新的播放。系统播控封面按图片内容复用，避免每次暂停、定位或状态保存都重新创建。

不可见时，手机播放进度与睡眠倒计时停止界面刷新；睡眠截止动作仍由播放器负责。手表后台释放由显示层启用的电量监测并停止方向采样，回前台立即恢复，前台电量与方向刷新频率不变。歌曲库存查重在离开 active 后取消排队查询及正在读取的大文件摘要，回前台通过原有队列重新查询，不丢弃发送任务；已经完成且有效的摘要缓存继续保留。

大文件摘要内存探针通过真实生产准备路径读取 3×512 MiB 稀疏文件，并与独立 SHA-256 参考比较，同时采样进程内存与检查活跃读取中的取消。也可在已启动的 iPhone 模拟器运行：

```sh
Tests/run-lan-memory-probe.sh IPHONE_SIMULATOR_UDID
```

批量文件探针使用唯一测试目录执行真实移动和删除，并还原传输索引。发送队列探针使用真实文件摘要、PhoneLibrary 和 HTTP 源准备，Watch 消息由测试端注入，覆盖立即入队、不可达时取消、单项失败隔离、去重、追加及分批。手机前台队列探针检查 `inactive` / `background` 暂停、恢复、重连对账、手动暂停及迟到消息隔离。

手表 LAN 探针使用本机 HTTP 服务。后台套件实际切换到模拟器“设置”App，确认真实 `background` 状态后检查系统下载、后台校验及进程重关联；`--foreground-only` 是该套件的兼容入口。`--inactive-only` 单独注入 inactive，只验证前台非活跃策略。进程崩溃和硬件熄屏、用户主动强退分别验收，模拟器结果不代表 TestFlight 真机效果。

```sh
python3 Tests/run-watch-lan-probe.py WATCH_SIMULATOR_UDID \
  --app /absolute/path/to/Debug-watchsimulator/WatchMusicWatch.app \
  --background-only
python3 Tests/run-watch-lan-probe.py WATCH_SIMULATOR_UDID \
  --app /absolute/path/to/Debug-watchsimulator/WatchMusicWatch.app \

```

暂停、继续及暂停后取消场景使用同一探针：

```sh
python3 Tests/run-watch-lan-probe.py WATCH_SIMULATOR_UDID \
  --app /absolute/path/to/Debug-watchsimulator/WatchMusicWatch.app \
```

同一下载探针的 `--range-only` 验证 HTTP 206 的范围和完整性校验。`--disconnect-resume-only` 与 `--foreground-only` 也可运行上述后台套件。

整批任务调度与单项隔离沿用参数 `--serial-only`，检查预提交任务的准确终态、单项失败和取消隔离，以及手动暂停和继续；不再断言网络下载严格串行：

```sh
python3 Tests/run-watch-lan-probe.py WATCH_SIMULATOR_UDID \
```
